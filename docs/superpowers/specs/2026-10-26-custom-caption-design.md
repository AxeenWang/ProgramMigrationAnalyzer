# 共用自訂標題列設計

使用者已確認主視窗及登入視窗一起改用自訂標題列，延續目前版本 1.0.1.0 及原有標題。Active Target 為 ProgramMigrationAnalyzer，Target Lock enabled，CodeLab-managed。

## 方案與範圍

採 WPF 內建 WindowChrome，讓拖曳、邊框縮放、雙擊及系統選單沿用 Windows 行為。自訂標題列使用現有深藍色，透過共用 Window template 與 WindowTitleBar 控制項保持兩個視窗一致。這比完全移除視窗框架後手動模擬行為更適合目前專案，也不需要新增 UI 套件。

主視窗提供最小化、最大化／還原及關閉。登入維持固定大小，只提供關閉。文字綁定 Window.Title，保留既有組件版本來源、工作列與 Alt+Tab 標題。關閉走原有 Window.Closing / Closed，不繞過登入取消與工作區清理。

Windows 11 自訂最大化區域回傳 HTMAXBUTTON。處理非客戶區滑鼠輸入、取消、移出與捕捉釋放，避免按鈕失效或重複切換。其餘區域交回 WindowChrome。命中判斷使用螢幕座標與 WPF 座標轉換，保留負座標與 DPI 邊界。

保持現有工具列、內容區、列表分隔線、最小視窗尺寸及登入輸入流程。標題列具有可辨識的按鈕名稱、鍵盤操作及最大化狀態切換提示。

## 驗證

先以既有 WpfChecks 證明現有視窗沒有共用自訂標題列，再驗證實際視窗中的文字、按鈕、原生命中判斷、最小化、最大化、還原及關閉。包含登入取消與驗證晚到結果、原有列表排版及分析功能。擷取真實 WPF 畫面做視覺檢查。

驗證前固定正式檔案版本，結束後比對雜湊。本次不提交、推送、發布或安裝套件。繼續使用現有 codex/version-1-0-1-title 分支，不移動原有三項版本修改。

Windows 貼齊可用的配置仍受原有最小 1100×720 尺寸與螢幕工作區限制，不為了增加配置而縮減既有版面底線。不同 DPI 與多螢幕的所有組合不宣稱已全面驗證。
