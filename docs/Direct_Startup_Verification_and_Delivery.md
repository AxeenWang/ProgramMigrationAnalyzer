# 直接啟動驗證與交付紀錄

日期：2026-10-26

## 變更

- 啟動直接顯示可操作的分析主視窗，關閉主視窗即退出。
- 移除登入、登出、帳號管理、離線 Key、授權匯入及公司發證工具的原始碼與 Solution 依賴。
- 移除公鑰驗證、嵌入及發布前置作業，直接執行 `publish.bat`。
- 保留文件載入、分析、報告、轉譯、預覽、Diff、輸出及工作區取消與釋放。
- 清除舊恢復副本中的登入相關原始碼，以及認證、發證與公鑰建置專案的遺留編譯產物。
- 修正發布時的中文亂碼，Windows PowerShell 管線統一使用 UTF-8，完成後還原原有輸出編碼，批次檔使用 ASCII 與 CRLF。
- 不修改既有外部帳號檔、Windows ACL 或金鑰，不清除舊版安裝資料。

## 驗證

| 項目 | 結果 |
| --- | --- |
| 修改前的 WPF 啟動斷言 | 失敗，確認舊版仍要求登入 |
| Solution Debug build | 通過，最初建置為 0 warnings、0 errors，清除殘留後最終建置為 6 個 NU1900 警告、0 errors |
| Phase2Checks | 通過，包含工作中釋放後忽略較晚完成的分析結果 |
| RegressionChecks | 通過，10 份樣本、.NET 8/10、4GL 草稿編譯與邊界輸入 |
| WpfChecks | 通過，直接啟動、可操作命令、既有畫面流程、關閉釋放與輸出保留 |
| PublishChecks | 通過，無 Key 發布、失敗與異常輸出保留原 EXE、保留 WebView2 資料，中文 UTF-8 輸出測試先失敗後通過 |
| 實際 `publish.bat` | 成功，沒有指定公鑰或 Key |
| 正式 EXE 啟動 | 實際桌面觀察到分析主視窗，開啟檔案及資料夾可操作，無登入或授權視窗 |
| 正式 EXE 關閉 | 透過主視窗關閉按鈕退出，未留下分析儀程序 |
| 獨立唯讀審查 | 未發現重要問題，分析與轉譯規則未變更 |

實際發布及最終補測建置時因網路限制無法查詢 NuGet 弱點資料，產生 `NU1900` 警告，發布與建置均 exit 0。這不是套件弱點檢查通過的證據。

正式 EXE 本輪驗證直接啟動與退出，完整功能流程由 WpfChecks 執行，未另測乾淨 VM 或客戶內網電腦。
